Driver pairing, locking, and unavailability are managed on the Fleet page's Roster tab — this view reflects it live but doesn't edit it.

Job pool

Every job, regardless of day — the day being planned is chosen on the Fleet side, since a job available today can still be deliberately booked onto a later day's truck if it isn't urgent.

Fleet — planning day

Fleet optimisation

Each truck has its own separate plan per day — pick which day's roster and runs you're building. A job doesn't have to match this day to be dragged in; if it isn't urgent, it can sit on a later day's truck instead of today's.

Priority sequencing decides which jobs auto-fill reaches for first — it changes what actually gets placed onto trucks below, not just how the list on the left is sorted. Shared-pickup clusters are placed together when they fit as one unit (more efficient), but split across trucks or runs when they don't — a shared pickup is a manual-allocation convenience on the left, not a requirement those jobs travel together. Efficient packing (Capacity, Location) always applies as a small tiebreaker underneath these five — not something worth ranking up or down, since nobody wants trucks used less efficiently. Shortest Run/Quickest Run are placeholders for real routing/traffic data; Cost weighs a job's revenue against what it costs to service, using placeholder rates. The comparison updates live as you reorder.
